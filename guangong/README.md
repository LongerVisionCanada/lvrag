# LVRAG

**LongerVision Retrieval-Augmented Generation · LongerVision 检索增强生成平台**

面向文化 IP、嵌入式智能终端与云端知识服务的可复用 AI 平台。

![关公（Guan Gong）——LVRAG 首个文化 IP 形象](docs/assets/guangong-hero.png)

> **首个 IP：关公（Guan Gong）** · 内部标识：`guangong`  
> **首个硬件目标：** [XiaoXiang ESP32-S3](https://github.com/LongerVisionRobot/xiaoxiang-esp32s3)  
> **当前阶段：** 项目初始化与本机 RAG 原型规划（尚未宣称已完成实现）

## 一、项目简介

**LVRAG** 不是某一个人物的聊天机器人，而是一套面向多个文化 IP 的 **离线优先、在线增强** 的知识与交互平台。关公是第一个落地的 IP；未来可扩展诸葛亮、李白等人物或其他专题知识体系。

核心目标：

- **离线可用：** 在 ESP32-S3 上实现有限语音命令、关键词问答、短故事与预置音频播放，不要求每次联网。
- **联网增强：** 利用专属关公 RAG 知识库提供长故事、背景资料、出处对照和多轮追问。
- **Agent 扩展：** 根据请求类型调用检索、LLM 或工具，不必每次都运行复杂的 Agent 流程。
- **控制成本：** 优先命中离线资料与缓存，服务器端统一管理 Token、TTS、额度及 API 密钥。
- **知识可迁移：** 一套经过整理的知识源，为嵌入式离线包和云端 RAG 同时提供内容。

## 二、四层 AI 架构

| 层级 | 运行位置 | 主要能力 | 是否必须联网 |
| --- | --- | --- | --- |
| **L1 · 设备与语音交互层** | ESP32-S3 | ESP-IDF/FreeRTOS、I2S 音频、按键、唤醒词、有限离线命令、Wi-Fi | 否（基础功能） |
| **L2 · 本地知识层** | ESP32-S3 Flash | FAQ、关键词/意图匹配、短故事、预录语音、简单缓存 | 否 |
| **L3 · 专属 RAG 层** | 本机开发环境 / Linux 服务器 | 文档解析、切片、Embedding、混合检索、出处引用、长故事 | 是（对 ESP32-S3 终端而言） |
| **L4 · 高级 LLM / Agent 层** | 后端 / 模型服务 | 千问等 LLM、多轮推理、工具调用、复杂问答及知识扩展 | 是（首版设计） |

典型交互：

1. 用户说“讲讲过五关斩六将”→ 离线命中短故事，直接播放。
2. 用户继续说“讲详细一点”→ 联网检索相关知识，生成长版本。
3. 用户追问“历史上真的如此吗？”→ 检索史料与小说，清楚区分史实、文学演绎和民间传说。
4. 用户提出跨领域问题 → 按权限和预算调用在线 LLM / Agent。

> **重要边界：** ESP32-S3 上的离线问答主要是预设知识与规则匹配，并不等于在芯片上运行完整的生成式大语言模型。文本能存入 Flash，也不意味着能离线将任意文字自然合成为语音；离线 TTS、音频文件容量等均需单独验证。

## 四、硬件与离线策略

初始目标是 **XiaoXiang ESP32-S3**，开发参考配置为 **16 MB Flash + 8 MB PSRAM**；最终以实际板卡及固件审计结果为准。

离线内容建议采用 JSON / 紧凑二进制索引等可版本化格式，包含：

- 问答项 ID、关键词、同义词、优先级；
- 短故事 ID、标题、正文、对应长故事 ID；
- 预录音频资源或资源路径；
- 知识包版本、校验信息和语言标识。

注意 Flash 同时需要固件、分区、OTA（如启用）、语音模型和文件系统空间。**16 MB 不是全部可供故事与音频使用**，应在设备实际编译和测试后确定知识包预算。

现有板卡工程独立维护，LVRAG 优先通过客户端组件和协议集成，不直接复制整套固件。

## 五、RAG 数据处理流程

```text
关公原始文档 / 原创稿件
           ↓
清洗、版权/来源核对、结构化与元数据标注
           ↓
按语义与事件切片（Chunking）
           ↓
Embedding + 全文/关键词索引
           ↓
检索（可选 Rerank）
           ↓
相关证据 + 对话上下文 + Persona
           ↓
Qwen / 可替换的 LLM
           ↓
带有出处区分的回答 / 故事
```

**RAG 不等于微调。** 第一阶段优先完善知识质量、检索效果、提示词和回答评测；是否微调，应在真实需求与评测数据充分后决定。

同一事件应允许生成两类内容：

- **离线短版：** 控制字数与播放时长，提前审核、可直接分发到设备；
- **在线长版：** 检索多份材料，补充上下文并明确史料与文学的区别。

## 六、服务端与费用控制

设备只连接自己的 LVRAG Backend，**不得在 ESP32-S3 固件中嵌入云端 LLM API Key**。

后端建议负责：设备认证、请求路由、RAG、缓存、模型网关、ASR/TTS 接入、用量统计、限额和内容更新。费用应至少分开统计 LLM 输入/输出 Token、ASR、TTS、服务器和检索服务。

商业化原则：让免费/未订阅设备仍可使用基础离线功能；在线服务通过设备额度、订阅或其他模式覆盖持续运营成本。价格与限额需根据真实使用数据评估。

## 八、开发路线

| 阶段 | 目标 | 验收重点 |
| --- | --- | --- |
| **P1 · 基础知识** | 确立人设、基础史料、首批 FAQ 和长短故事 | 出处清晰、内容可追溯 |
| **P2 · 本机 RAG** | 在开发主机上完成导入、索引、检索和问答原型 | 能检索到正确片段，区别史实与小说 |
| **P3 · ESP32-S3 离线原型** | 封装本地 FAQ、故事及语音入口 | 断网运行、容量与延迟实测 |
| **P4 · 云端对接** | 后端 API、在线 RAG、LLM、ASR/TTS | 端到端交互、引用及费用观测 |
| **P5 · 产品化** | 用户额度、缓存、知识版本更新、多 IP 扩展 | 安全、稳定、可维护 |
